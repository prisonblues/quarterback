# a brake can reach its verdict and be told not to apply it

This repo has a rule — instrument before you gate — and had no mechanism for it. Every brake
shipped either off or armed, so the only way to learn what a new one would have done was to arm it
and find out on live cycles. That is why `escalate_on.fix_injection`'s `0.5` was still uncalibrated
long after it became load-bearing: not for want of a number, but for want of a population. A false
positive rate needs cycles that went well to have a denominator at all, and no cycle carrying an
attributable round has ever been recorded as converged (0 of 27), with 128 of 201 new findings
across seven PRs written by the fix pass immediately before them.

`review_panel.escalate_modes` gives each rung one of two words. `shadow` runs the rung's decision
and records its verdict, applying nothing — no stop, no veto line, no `confident: false`. `enforce`
is the same decision, applied. **The decision function is the same function in both**, which is the
property this buys rather than an implementation note: a shadow rung produces the record an
enforcing one would, so the population that calibrates a threshold exists before the threshold
binds, and arming a rung is a config change rather than a release.

**Every rung that exists today ships `enforce`, and that is the rule rather than a hedge.** The
default is `shadow` for anything *new*, and none of the six is new; a key that shipped `shadow`
across the board would silently disarm five brakes that are armed, and the first cycle after the
upgrade would run with nothing stopping anything and nothing on the round looking different. A rung
added later and not named in the defaults resolves to `shadow` by arriving, without anybody
remembering the rule. A rung a repo's own file fails to name falls back to the default and never to
`shadow`, so one repo naming one rung cannot disarm the other five, and an unreadable word takes
the same fallback: a typo may cost a calibration and may not cost a brake.

**It is a sibling mapping rather than a `mode` inside each rung**, which is not the shape the issue
described. Three reasons, and the third decides it: every rung is a scalar and the board stores one
opaque JSON value per dial, so turning a number into an object is a new value shape at the board
and in every consumer that has read the rung as a number; the dial layer answers "which layer set
this" per leaf, and a threshold from the repo's file beside a mode the board set for an afternoon
is exactly the split it exists to report; and key validation descends two levels, so a mapping one
level deeper would take no allowlist and `{"mdoe": "shadow"}` would be an unchecked typo in the
block that decides when cycles stop.

**`fired` is split where the split was always latent**, and the vocabulary stays one vocabulary.
`over` is the measurement crossing, unchanged. `would_fire` is the verdict the rung reached — over,
armed, its own bounds cleared, everything except the mode. `fired` is `would_fire` and `enforce`.
So `fired` keeps its exact present meaning and every consumer of it is correct without an edit: a
shadow rung stopped nothing, is not why the cycle stopped, and buys no constructive fan-out. Both
flags and the mode ride each rung's payload block, so the calibration population is readable, and
nothing is billed for what is in the shadow list — a consumer that spent on it would have turned an
instrument back into a gate by another route.

**A shadow rung may not touch `stop`, `reason`, `veto` or `confident`**, which are what they would
have been with the rung absent. A shadow verdict that vetoed a confident stop would be enforcement
by another route, and a lost `confident` is a landing hold two files away — so a brake shipped in
shadow to be calibrated would hold pull requests while calibrating. It is still visible in the one
field a human reads: the stop reason carries a trailing clause naming each shadow rung that would
have fired, in the word `shadow`, appended after the sentence the stop already had so that sentence
is byte-for-byte what it was. A reason naming a rung without naming its mode is the misread this
was filed over — a rung that would have fired is not a rung that fired, and reading the first as
the second is how a confident round gets described as divergence.

**Four rungs are gated on the mode, not six.** `new_findings_not_falling`, `fix_injection`,
`unrefereed_fix` and the guard-churn ceiling publish `mode` and `would_fire` and consult the mode
before applying. `premise_repeated` and `premise_undecidable` carry a mode in the config mapping,
but their stop is applied elsewhere off a list rather than off a measured state block, and nothing
reads their mode yet — so they publish no `would_fire` and appear in no shadow list, because a
payload saying `shadow` beside a cycle the rung ended is the exact failure this was filed over.
Rungs that gate nothing at all — the fix surface and blast-radius instruments — get no mode for the
opposite reason: there is no verdict for a mode to withhold.

The way back, and the way in, is one word per rung. `"fix_injection": "shadow"` runs that number
over live cycles and records every verdict it would have reached while changing nothing about what
stops, which is the measurement #637 could not take. It is not set in this repo, because at six
rounds that rung is one of the brakes that actually ends a cycle and standing it down is a decision
about how much divergence to run through unbraked — a person's call, in one word, with the way back
in the same word.
