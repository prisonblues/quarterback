# the CI header no longer says a suite ran on this commit when nothing ran anywhere

`ci_brief`'s header read *"the repo's own test suite, run on this exact commit"* for all nine
states it can report — including `none`, where no run exists anywhere; `blocked`, where a run
object exists and has executed nothing; and the three `local-*`, where a suite did run and it
was not CI's.

So on five of the nine a seat was told in one breath that the suite ran on this commit and in
the next, by the body, that it had not. A model resolving that contradiction unaided resolves
it in whichever direction it likes, and the direction that costs is treating an absent run or
a local pass as CI evidence for a commit.

Every body is unchanged; only the parenthetical moves, and the label stays `CI` for all nine.
A header that varied its label would let a seat skim it and miss the distinction the body
spends a sentence making — these are the same question about the same commit asked of two
sources of differing strength, which is what one heading with a careful body says and two
headings do not. So the invariant half is the half a skimmer reads, and the half that varies
is the clause that was making a claim.

For the local states the correction is *"not CI's"* rather than *"not this commit"*: the
runner already gates a local run on the checkout being at the PR's head, and a pass whose tree
moved underneath it is downgraded rather than reported at the wrong sha. `local-unknown` says
**attempted**, because it also covers a suite that never started.

A tenth state cannot inherit a sentence that is false of it. The table is pinned by a test
that reads the states off the two vocabularies rather than off a list somebody has to remember
to extend, so adding one goes red. `ci_brief` itself falls back to the `unknown` wording — the
only entry in the table asserting no run at all — rather than raising in the middle of a
prompt render.
