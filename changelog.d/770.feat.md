# how dangerous the repair is, read off the paths it touches

A finding is graded on severity and nothing else, so a fixer is told how bad the defect is and
never how far the repair reaches. On lexray#1780 a round-3 pass answering a P2 about one route put
`gzip` at nginx *server* level and broke an unrelated endpoint's conditional requests. Nothing in
that finding said the fix reached past the line it named, because nothing anywhere computed it.

The blast-radius classifier is a pure function from a set of changed paths to a risk lane — `low`,
`medium` or `high` — with the categories that fired and a sentence naming the file that fired each
one. Schema migrations, auth/security/payment code, secrets, deploy and production config, and
irreversible infrastructure are `high`; dependency changes, public API changes and source changed
without tests are `medium`; generated files are `low`. A change's lane is the *maximum* over the
categories that fired, never a sum and never an average: two medium signals are not a high, and an
additive score would need re-tuning every time a category was added.

**Derived, never asked of the model.** A number a model reports about the risk of its own work is
an uncalibrated self-report, and the actor scoring its own fix is the one the injection figure
already indicts. This is a rule table over path strings. It consults no reviewer's words, no
severity, no confidence, no network, no clock and no repo read — the same bytes give the same
answer whether it is called mid-round, from a test, or from a replay over recorded rounds.

**Two guards do most of the calibration work**, because the naive version over-fires spectacularly
on the repos it has to serve. A generated or vendored path contributes only its named categories
and is never word-matched: lexray carries 2,855 files under a vendor assets directory, three of
them FontAwesome's Stripe brand icons, and without the guard an icon refresh reads as a payment
change. A prose or test path is likewise never word-matched: that repo's security documents and
twenty-one legal-schema files carrying `stripe` in their names are documents *about* dangerous
things, not code that does them. The guards suppress and never promote — anything the table cannot
classify is scanned, because a path it does not understand must not be excused. And every diff
heuristic fails toward the lower lane: only lines positively identifiable as additions inside a
well-formed hunk are read, so an unparseable diff yields no categories and can never manufacture a
`high`.

**It is pointed at the fix pass, not at the pull request**, and it is reported and gates nothing.
It rides the round's payload beside the fix-surface measurement, it moves no stop, no reason, no
veto and no confidence, and there is deliberately no dial to arm it. That is this repo's
instrument-before-gate rule: an instrument earns a gate over a few dozen cycles or not at all.

**The lane is stored; its working is not.** `review_runs.fix_blast_lane` keeps the three-value
answer per round, readable on `GET /reviews`, `GET /review/{id}` and per round on
`GET /review/findings`, with a lane distribution on `GET /review/convergence` that moves none of
the numbers that endpoint already publishes. The categories that fired, the paths behind them and
the sentence rendered from both stay in the payload and are dropped by design: a reader asking
about one round has that round, and the lane is the worst of the categories, so a column for them
would be one value in two places with two chances to drift. What earns the column is the only
question that cannot be asked later — across hundreds of rounds, do fix passes landing in
dangerous code write more of the *next* round's findings? The payloads it was computed from live
in a temp directory on whichever host ran the panel, so a lane not stored today is a correlation
nobody can compute when the axis needs calibrating.

**Say plainly what this is: one input to the risk axis and not the axis.** The axis the issue asks
for — a `fix_risk` grade a finding carries, so that a dangerous repair must be narrowed and must
declare its collateral — takes three inputs, and this is the one that needs no history and no
model. The other two are the finding's own measured injection history bucketed by category and
raising seat, and the breadth of what a finding says must move with it. Neither is built. What
`high` should gate, and whether it should gate anything at all, is an open decision carrying
`needs-human/decision`, and arming this before that decision is made would settle it by accident.

**Null where nothing was measured, and never `low`.** A round with no readable fix range — round 1,
or a rewritten range — gets no lane at all. The classifier answers `low` on an empty path list,
correctly, for a pass that genuinely touched nothing; manufacturing that same `low` out of an
absent measurement would be the flattering direction on the one axis that exists to say a change is
dangerous.
