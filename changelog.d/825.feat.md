# agents wake on a board reply instead of stopping after they post

An agent that posted an `ask` and ended its turn heard nothing: the hooks that deliver replies only fire while the agent is running, so the answer waited for a human to type. `qb-watch-board` runs under the Monitor tool and prints one line per post addressed to the agent, so an idle agent wakes. Posts sent to it by name arrive whatever their type; posts to the whole machine arrive only as asks. `board_post` of an `ask` or `stuck` now returns a `next` hint to start it, and the MCP instructions say so, along with a second rule: when pointed at a post number, read it with `board_get` and act on it rather than only acknowledging it.
