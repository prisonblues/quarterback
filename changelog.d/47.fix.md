# the most-edited file in the repo was the one nothing linted

`harness/` was excluded from ruff wholesale, and the exclusion's own comment ended
"reconciling the harness onto its own ruff config is tracked separately" — which it was
not. Meanwhile `panel.py` became the most-edited file in the repo. The cost was concrete:
`ci_txt ={"PASS": …`, a missing space with its continuation left at the old indent,
reached review on #34 and was caught by an LLM reviewer reading the diff, because nothing
mechanical was looking. The cheapest possible defect, found by the most expensive possible
reviewer.

The directory is linted now, and `panel.py` went from ~270 findings to 4.

### The exclusion's premise had expired

It said the RUF100s fire "because this config does not enable E402". `E` is selected, E402
is on, and there are four real E402 findings in there. The 326 directives are unused for
the opposite reason: **ruff tolerates the `sys.path.insert` idiom that pycodestyle flags**,
so they suppress nothing here and remain correct everywhere else. Stripping them — which
is what `--fix` does — would have made the files worse under any other linter, which is
what the original comment was right about for a reason that had stopped being true.

### `ruff check --fix` is not safe on this tree

It twice deleted `import _path_sandbox` from `test_qbdata.py`, which is imported for the
side effect of building that suite's PATH and HOME. Only `test_path_sandbox.py` — a guard
written for exactly this — noticed. `import panel_seats  # noqa: E402  — these seats moved
here in #129` is the same shape. So F401 is not auto-fixed, and the one that keeps being
deleted now carries a `noqa` and a sentence saying why.

Applied here, all verified against both harness suites and the app suite: UP017, UP037,
UP033/35, RUF010/21/68, F541, SIM300/905, W291/293, E401, and I001 across 59 files —
checked that nothing moved across a `sys.path.insert` boundary. Not applied: RUF022, which
sorts `panel_core`'s `__all__` flat alphabetical and destroys the grouping-by-meaning the
comment above it describes, for 257 lines of churn.

### CI runs it, and blame skips it

Ruff had been configured since v2.13 and run by nothing — no job, no hook, no flake check.
A `ruff` job now gates every pull request. It cannot cry wolf: the tree is at zero when
this lands.

Zero is reached partly by ignoring 17 rules whose 97 findings each need a judgement a
`--fix` cannot make. That is a ratchet rather than a clean bill — the gate is live for
everything else, which is what would have caught #34 — and the block naming them says so
and points at #697.

`.git-blame-ignore-revs` lists the two formatting-only commits, so `git blame` names
whoever last changed a line's logic instead of whoever last ran a linter. GitHub reads it
automatically; locally it needs a config key a repository cannot set for itself, so
`qb-hooks install` now sets it per checkout — which is also per worktree, the granularity
it actually needs.
