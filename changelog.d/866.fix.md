# a panel re-review given `--baseline` continues the cycle instead of starting a new one

On nix-fleet#162, three panel rounds ran with `--class-ledger` and `--baseline` but no
`--round`. Each run defaulted to round 1, so the baseline was refused as "not earlier than
this run's round 1", and each re-review started a new cycle. `fix_injection` and the
cycle's provenance never applied across the rounds. Round 1 also recorded `cycle: null`,
because a class-ledger round did not count as part of a cycle.

`panel.py --baseline …` without `--round` is now the round after the latest baseline it
accepts, and continues its cycle. A re-review that used to run as a fresh round 1 is now
counted against the round cap, so one past the cap is refused, and the refusal names the
baseline the round came from. A `--class-ledger` round is a cycle round, so its round 1 names the
cycle. A run that cannot continue its PR's cycle now says so on stderr and in the config
notes the summary prints, instead of quietly starting round 1: a `--baseline` none of
whose payloads is accepted, a later round with no baseline, or a class ledger with earlier
rounds and no `--baseline`. A non-UTF-8 baseline file is now reported as unreadable rather
than ending the run.
