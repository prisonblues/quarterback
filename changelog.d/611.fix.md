# qb-doctor and qb-catchup stop disagreeing about whether work exists anywhere else

`qb-catchup` grew four guards on the "does this work exist nowhere else" question for #573.
`qb-doctor`'s `unpushed` row, which asks the same question of the same checkout, grew none of
them: its `_maps_every_head` compared the SOURCE half of a fetch refspec against
`refs/heads/*` and read nothing else. So on four real configurations the sweep refused the
question and the doctor answered it — loudly, out of tracking refs it had no business
trusting.

| configuration | `qb-catchup` said | `qb-doctor` said |
|---|---|---|
| `remote.origin.fetch = +refs/heads/*:refs/cache/origin/*` | refused | `fail`, whole history counted stranded |
| `^refs/heads/private/*` alongside a covering refspec | refused | answered; the excluded branches read as stranded |
| `refs/remotes/ghost/main` left by a removed remote | refused | trusted it, and subtracted whatever it reached |
| a `git config --get-all` that failed | refused, naming the exit code | "does not fetch `refs/heads/*`" — a fault it had not established |

The last one is the quiet one. `git config --get-all` exits 1 for "no such key", which is a
fact about the configuration, and anything else is a git that would not answer; conflating
them names a configuration fault that may not exist and sends the reader to fix the wrong
thing.

The three that trust an unrefreshed ref fail in the direction that loses work: a
`refs/remotes/` namespace nothing fetches never self-corrects, so it is a permanent licence
for local-only commits to read as safely elsewhere.

### Ownership is a refspec destination, never a remote name

The audit asks each refspec **where it writes** rather than comparing the top path segment
under `refs/remotes/` against configured remote names. That comparison fails open twice: a
remote writing to `refs/remotes/origin/branches/*` does not own `refs/remotes/origin/old`,
and with `team/alice` configured an orphaned `refs/remotes/team/bob/` reads as covered
because a name happens to share its first segment.

### What keeps them together now

One tool is shell and the other Python, so the logic is duplicated and cannot be shared.
`test_the_two_tools_refuse_the_same_configurations` executes **both** against one checkout
per configuration and compares the verdicts, rather than grepping two sources for a literal
— a grep proves a string is in a file, never that it is on the live code path. It fails the
moment either side grows a guard the other has not.
