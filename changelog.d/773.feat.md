# a refuted finding was raised again next round, because nothing ever read the refutation back

The board has recorded a `refuted` outcome since v2.37 and no round has ever consulted one.
So a seat that raised a false positive raised it again, the judge ruled on it again, and the
fix pass either re-refuted it — which #616 measured as costing *more* than complying — or
complied with something that was wrong. The loop's cheapest path was to comply with a finding
nobody believed, and the resulting change is unnecessary churn that reads as diligence.

`GET /review/refutations` is the read that ends it. A round now fetches the set once and
consults it twice: the refutations are rendered into the reviewer prompt before the seats
dispatch, and a finding standing where a refutation stands is dropped from the clusters
before the judge is called. A finding never raised costs no ruling, no fix-pass line, no
payload row and no place in the next round's baseline.

### The reason is what binds, not the verdict

Every row carries the sentence its writer recorded, because that is the only form a later
reviewer can check against the code in front of it. Told "this was wrong" a seat can only
obey or ignore; told *"`make lint` only checks src/ and scripts/"* it can go and look. A row
with no reason is not published at all — both write doors already require one, and a bare
refutation is binding text with no argument under it.

Two writers, kept apart on the wire: `POST /review/outcomes` with `outcome: refuted`, and a
`POST /review/ledger` entry with `state: refuted`, whose `source` says whether it was the
judge, a fix pass or a person. A judge's `dismissed` verdict is deliberately **not** one — it
is a ruling made inside one round on that round's material, and nothing ever required it to
state a reusable reason, so binding it would carry a context failure forward for the life of
the pull request.

### Matched by locality, never by wording

A refutation keyed on the seat's phrasing misses the reworded restatement, which is the
failure #771 fixed. The comparison is `panel_locality.same_finding` — file plus line span
within three lines of slack — so a reworded finding is still suppressed and a defect whose
lines drifted when the fix above it landed is still the same defect. A refutation naming no
line reaches the seats as prose and binds nothing at all, because path equality on a long
file would declare every unplaced finding in it to be every other one.

### One pull request, and the suppression is loud

A wrong entry silently suppresses a real finding later, so the blast radius is one PR by
construction: both parameters are required and no parameter widens it. Promoting a refutation
to repo-wide is a deliberate act and is not built here.

Every drop is named in `config_notes` with the place the finding stood, and the payload's
`refuted.suppressed` carries the key and the reason each rests on — enough to go and read the
argument and amend the outcome if it is wrong. The seats are given the same escape hatch in
one line: a disputed refutation is a `could_not_assess` phrase, never a re-raise, because a
re-raised finding is dropped before the judge and so argues with nobody.

It fails open throughout. An unreachable board, a board older than the feature, a matcher
that throws — each leaves the round exactly as correct as every round before this existed,
and says so. A memory that cannot be fetched must never cost a round.
