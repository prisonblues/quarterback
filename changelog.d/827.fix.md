# a slow `git status` no longer stalls every prompt

`qb-hook`'s sync note ran `git status` with no bound. On a WSL checkout under `/mnt/c` that
call sits in D state on the 9p bridge for a minute or more, and the note is built on every
`UserPromptSubmit`, so a trivial prompt took about 70 seconds (board finding #27975).

Every git call in `_sync_note` now runs under `timeout 3` and fails open, so a slow checkout
costs the turn its sync note rather than the turn. When `status` is the call that times out,
`dirty` is left out of the `/sync` request instead of being sent as `false`: an unknown tree is
not a clean one.
