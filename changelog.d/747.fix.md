# the scoping warning that fired on most rounds and was true on almost none

A panel round warned that its target `may be MIS-SCOPED` whenever GitHub's stored base for the PR
disagreed with the fork point, and told the reader to re-check every finding against a range by
hand. The check rested on a claim about `gh pr diff` that is not true. `baseRefOid` is the base
branch's TIP as of the PR being opened or of the last push to the head branch, so it differs from
the fork point on every branch cut from an older commit than that tip — a third of the open PRs
measured on one active integration branch. `gh pr diff` does not build from that commit: it serves
the three-dot diff from `merge-base(baseRefOid, head)`, which in exactly that shape IS the fork
point. So the note fired constantly and named a range identical to the one already under review —
measured on `lexray#1656`, where the two agreed on file set, line counts and per-file numstat.

The cost was not the wasted check. `config_notes` is where the load-bearing scoping caveats live —
a `scope: "pr"` fallback, a rebase inside the range, a truncated comparison — and the panel skill
tells an orchestrator to read that section before believing a round was scoped. A caveat that is
always present and never true trains a reader to skim the section that has to be read.

The condition the note was originally filed for is real and survives, narrowed to it. When the base
branch has absorbed commits the head branch also carries and no push to the head branch has
recomputed the stored base, that stored base is an ancestor of the head, the diff is built from it,
and it now sits behind the true fork point — so the round really does review code that has already
landed. That is what PR #187 was, and a round spent fifteen judge-confirmed findings on it. A round
now asks what `gh pr diff` actually used — the merge base of the stored base and the head — and
warns only when that differs from the fork point. The extra call is made only on the PRs where the
cheap comparison disagrees, and where it cannot be read the round says the target is unverified
rather than claiming it is wrong.

Reconstructed rather than argued from the field's documentation: three pull requests built to hold
each shape confirm that `gh pr diff` returns the merge-base three-dot diff in the common case, and
returns already-landed code in #187's.
