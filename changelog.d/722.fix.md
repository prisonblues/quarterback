# the plan stops offering a review that already happened

A panel review round claims the PR it is reading (#715), so that `GET /active` can say which
agent is spending money on which PR rather than showing a reviewer three hours in exactly as it
shows one that has just opened the repo. Every issue or PR claim also writes that repo's plan
item, at rank 1, because picking work up is the one act that should put work on the board
(#427).

Both are right, and together they are wrong. A round starts and the plan gains an item for PR
#n at rank 1, claimed. The round ends and hands the claim back. The item stays: open,
unclaimed, unblocked, rank 1 — and `plan_read` computes `next` as the first open, unclaimed,
unblocked item, so the following agent was offered a review that had already happened, above
whatever a human had actually ordered. Read off this board while the issue was open: `next` for
this repo was the item for PR #715 — the PR that added the claim — open at rank 8,
`rank_source: picked-up`, its claim released, ahead of every ordered item below it.

`POST /claim` now takes `plan_item: false` — **a claim that records exclusivity without
asserting a pickup**, which is the distinction the board was missing. `qb-claim
--no-plan-item` is the flag, and a review round takes its claim with it. The default is
unchanged and has to be: a real pickup is exactly what #427's rule is for, so every caller that
has not heard of this goes on putting its work on the board.

The flag does one thing. It does **not** retire an item that is already there — "do not write
one" and "retire the one you find" are different powers, and the row a round would clear may be
a human's, or a real pickup's by an agent still working; the claim path cannot tell. It does
not weaken the claim, which is still exclusive and still refuses a second holder with a name to
talk to. And a renew carrying it writes nothing rather than repairing, since a round renews for
as long as it reviews and a repairing renew would put the PR on the plan on the second
heartbeat.

Rejected: teaching the board that a PR claim is never a pickup. Sometimes it is exactly that —
an agent taking over somebody's stalled PR to finish it — and nothing in the key can tell the
two apart. The caller can, so the caller says.

### The rollout, because the two halves ship separately

This is a protocol change on a fleet where the harness and the board are deployed independently,
so mixed versions are the ordinary state of a rollout rather than an edge case — and both
directions fail, differently. **Board first, then the harness.**

A new `qb-claim` against an old board is the silent one: `ClaimIn` takes pydantic's default
`extra="ignore"`, so the field is discarded and the rank-1 row is written anyway. The answer
carries the evidence — a `plan_item` on a request that asked for none — and nothing read it, so
the tool reported a clean claim over the exact defect it had been upgraded to prevent.
`qb-claim` now reads the answer back and says `WARNING: --no-plan-item was IGNORED` on stderr,
worded deliberately unlike the reassuring pickup line beside it; `hold_pr` carries it into
`config_notes`, which is what `--post` publishes. The claim is never failed over it: nothing out
here can un-write the row, and the claim is the half that prevents duplicated work.

A new round against an old `qb-claim` is the loud-but-wrong one: argparse refuses the flag and
exits 2, which `hold_pr` filed as "the board did not take it" — so a host part-way through an
upgrade ran every round **unclaimed**, silently undoing #715 a few hours after it shipped. That
refusal is now told apart from a board's (argparse's own wording, plus the flag's name, so a
different unknown argument is not retried into the identical refusal) and the claim is asked for
again without the flag, noting that a plan item was written after all. An imperfect record
somebody can see beats no record at all.

`hold_pr` returns `(note, holding)` for this: a note used to imply "and the claim is not ours",
which both cases above break — a round can hold the PR and still have something to say about
how. Inferring one from the other would have skipped the release on exactly those runs and left
the PR held for three hours.

One consequence, in the round: `--title` and `--no-gh-title` go with the item, because the plan
item was the title's only consumer. `qb-claim` reads `--no-plan-item` as implying
`--no-gh-title`, so the saved `gh` call per round is not lost with them, and a title passed
explicitly beside the flag is dropped rather than sent to be discarded at the other end.
