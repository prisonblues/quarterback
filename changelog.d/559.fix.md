# a fix pass that restores reviewed code no longer reads as the pass that wrote it

The panel decides whether a round's findings were introduced by the fix pass before it by asking
which lines that pass added. A revert of a revert adds code an earlier round already reviewed, so
the pass that repairs a bad revert was scored as having authored all of it — about ninety lines in
the case this was measured on. That number is what `escalate_on.fix_injection` ends a cycle on, and
since the round cap moved from 2 to 6 it is the thing that ends cycles rather than a footnote on a
round the cap was ending anyway. So the correct response to a `fix_injection` stop inflated the
statistic that produced the stop.

Attribution is now content-aware. A run of five or more consecutive added lines that is
byte-identical, in order, to lines the same file carried at the head of an earlier round of the
cycle — and that the file no longer carries at the commit the fix range starts from — is a
restoration, and is left out of the attribution. The round says in `config_notes` how many lines it
took out and which rounds it compared against, and records the same in a new `provenance_restored`
payload field.

Both ends of that, because restoration is a round trip: the content was on the branch once, and it
had gone. A block the branch never lost is a copy the fixer pasted, and a copy-paste defect is one
of the commoner things a fix pass introduces.

The boundaries err toward leaving a line with the fixer, because a brake that cannot fire is worse
than the miscount it replaces. A run of four does not qualify, a line that merely recurs elsewhere
in the file does not, and the commit the range is anchored on is not consulted at all — code that
was already there and still shows as added is a copy or a move the fix pass made. Reading a file as
an earlier round saw it needs a local checkout, and a round that has none says the comparison could
not be made rather than reporting an unfiltered number as a filtered one; one that could read only
part of the cycle's history names the rounds it missed, and a file whose version at the start of
the range could not be read is dropped from the filter rather than matched on half the evidence.

The diff walk behind all of this now splits on the newline alone. It split on `str.splitlines()`
before, which also breaks on a form feed — so a source line carrying one counted as two added lines
and shifted every line number after it, placing findings against the wrong lines.
