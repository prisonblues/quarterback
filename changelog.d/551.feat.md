# a fixed fix budget is a bigger share of a smaller change, and the low-severity budget now knows it

`low_severity_fix_lines` is an absolute — **40** churned lines the whole round may spend on the band
between the two floors — with no proportional companion. On a 179-line PR that is a sane ~22%
allowance. On a 30-line PR it is larger than the change.

### the direction matters, and the obvious argument gets it backwards

The tempting framing is symmetry with the growth ceiling: #664 has just put a **floor** under
`max_fix_growth`, so surely this wants one too. It does not, and stating the reason carelessly
produces the wrong operator.

`max_fix_growth`'s defect is that a proportional allowance shrinks with the PR while diff framing
does not, so a tiny PR cannot afford one honest fix — that wants a floor. What `low_severity_fix_lines`
measures (#297) is **accumulation relative to the change**: PR #188's feature came out of two fix
passes at 721 churned lines, 74% of it review-response code. Its dangerous end is therefore the
**small** PR, where a fixed 40 lines can exceed the diff it is polishing. On a 5,000-line PR, 40
lines of P3 work is not the failure mode — it is noise, and harmless noise.

So the companion is a **ceiling**, not a floor. Same question, opposite operator; a floor written
here on the strength of the one next door would reintroduce #188.

### `low_severity_fix_full_chars`, at 14,325

```
budget = min(low_severity_fix_lines,
             low_severity_fix_lines × first_chars ÷ low_severity_fix_full_chars)
```

A **size**, not a rate: the first round's `pr_chars` at or above which the whole line budget applies,
with anything smaller getting it pro rata. Both halves are ceilings, so the pair can only ever
**tighten** — the outer `min` is on the written value, so no setting of the size can hand back more
than the file wrote. The first round is the denominator for `max_fix_growth`'s own reason: a budget
that grows as the PR grows pays for the growth it is supposed to bound.

**Chars, and that is a correctness point rather than a style one.** The budget is counted in churned
lines and the only first-round size a baseline records is `pr_chars`, so the companion had to be
written in one unit or the other. Written in chars, the ratio of two char counts multiplies a line
count and the units cancel: nothing converts, the crossing is stated in the unit the code actually
compares, and the value cannot inherit #692 — where PR #188's char count reproduces and its
churned-line count does not.

**14,325 is measured in chars rather than converted into them.** #551's policy is a ratio, which puts
the full budget at about 40 ÷ 0.22 = 182 churned lines. Rather than multiply that by an assumed rate,
every merged PR of this repo whose churn is between 120 and 260 lines (**n=21**) was fetched, measured
in characters, and scaled to exactly 182 churned lines: **median 14,325**, range 9,538 to 18,604. It
is the size PRs of that shape actually are, the measurement is re-runnable, and the spread is stated
rather than hidden — n=21 supports a median, not a fourth significant figure.

| first round (`pr_chars`) | budget |
| ---: | ---: |
| 2,000 | 5 |
| 5,000 | 13 |
| 10,000 | 27 |
| 14,325 and up | 40 |

### the budget is clamped at one honest one-line fix

Pro rata alone reaches 1 line at 359 characters and 3 at 1,075. A budget of one or two lines is not a
small budget — it is "fix nothing" written so that it reads like a budget.

`git diff --numstat` reports a **changed** line as one insertion plus one deletion — verified, and
`referee_split` counts churn the same way — so the cheapest correction to a line that already exists
costs 2, and the commonest below-floor fix is a comment or a stale docstring, which
`unrefereed_line_weight` prices at 2 apiece. The clamp is therefore `2 × unrefereed_line_weight`,
**4** at the shipped weight, moving with the weight because the weight is the unit the budget is
counted in.

**Since #674 a starved budget is expensive rather than untidy.** A fix the budget cannot pay for is
declared `--declined <key>:budget`; the declaration appends a veto; the veto costs the round its
`stop_confident`; and `preland --require-earned-stop` turns a false `stop_confident` into a failed
check. A budget too small to buy anything does not merely fix nothing — it holds the PR out of a
strict landing for the rest of the cycle.

Below 1,791 characters the clamp *is* the budget — that is where pro rata first pays for a
second such fix. That is a
concession and is written down as one: on a PR that small there is no proportional answer that is
also a workable one, and #674's price is why it concedes toward the workable.

### what it will not do

**It can never raise a budget.** The clamp sits inside `min(written, …)`, so a repo at
`low_severity_fix_lines: 3` gets 3 and not 4. A written `0` — which raises the applied floor to the
trigger cut — is left exactly where it is.

**A size with no absolute beside it bounds nothing.** At `low_severity_fix_lines: null` there is no
smaller half to take, and the size does not become a budget on its own — a repo that wrote "no
budget" must not get one back from a key it never touched. The round says so in `config_notes`.

**Nothing changes about which findings are on the budget, or the order they are spent in.**
Cheapest-first has no value term deliberately, and reintroducing one hands back exactly the
judgement #297 removed.

`null` is the proportional half off and the exact pre-#551 behaviour, settable from the board on its
own — which is what makes a shape decision reversible without a release.
