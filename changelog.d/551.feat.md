# a fixed fix budget is a bigger share of a smaller change, and the low-severity budget now knows it

`low_severity_fix_lines` is an absolute — **40** churned lines the whole round may spend on the band
between the two floors — with no proportional companion. On a 179-line PR that is a sane ~22%
allowance. On a 30-line PR it is larger than the change.

### the direction matters, and the obvious argument gets it backwards

The tempting framing is symmetry with the growth ceiling: #664 has just put a **floor** under
`max_fix_growth`, so surely this wants one too. It does not, and stating the reason carelessly
produces the wrong operator.

`max_fix_growth`'s defect is that a proportional allowance shrinks with the PR while diff framing
does not, so a tiny PR cannot afford one honest fix — that wants a floor. What `low_severity_fix_lines`
measures (#297) is **accumulation relative to the change**: PR #188's 185-line feature came out of
two fix passes at 721 churned lines, so 74% of that PR was review-response code. Its dangerous end
is therefore the **small** PR, where a fixed 40 lines can exceed the diff it is polishing. On a
5,000-line PR, 40 lines of P3 work is not the failure mode — it is noise, and harmless noise.

So the companion is a **ceiling**, not a floor. Same question, opposite operator; a floor written
here on the strength of the one next door would reintroduce #188.

### `low_severity_fix_pct`, at 22.4

```
budget = min(low_severity_fix_lines, low_severity_fix_pct × the cycle's first round)
```

Both halves are ceilings, so the pair can only ever **tighten**. The first round is the denominator
for `max_fix_growth`'s own reason: a budget that grows as the PR grows pays for the growth it is
supposed to bound.

**22.4 is the allowance the absolute already grants.** 40 / 179 = 22.35% — the "sane ~22%" measured
on the one run this dial has been watched on, a 179-line PR that spent 31 of its 40 lines and
dropped a 17-line fix against 9 remaining, which is the dial working rather than failing. The
crossover follows at **178.6 churned lines**: at or above it the absolute binds and nothing changes,
below it the proportion does. Rounded *up* from 22.35 rather than down, because a ceiling should not
tighten the case its own calibration says is fine — so that run keeps all 40 of its lines and this
key is a provable no-op on every run anybody has measured.

| PR (churned lines) | budget |
| ---: | ---: |
| 30 | 6 |
| 100 | 22 |
| 178 | 39 |
| 179 and up | 40 |

### the conversion, re-measured

A baseline records the first round's size only as `pr_chars`, and this budget is spent in lines, so
one rate is unavoidable: `panel_seats.CHARS_PER_CHURNED_LINE`, **58**. That is PR #188's own merged
diff — 34,635 chars over 597 churned lines — and it is **not** the 34,717-over-521 (66 a line) that
`max_fix_growth_chars` calibrates against. The char count reproduces on today's PR; the line count
does not, and neither does #297's 721 for the same PR, so both line counts look to be from a
pre-rebase state nothing can now read. 66 is left where it is rather than corrected on a guess, and
this key uses the number that can be reproduced.

Cross-checked against this repo's last 25 non-merge commits, which run 60-95 chars a churned line
with a median of 81. **58 sits at the bottom of that on purpose**: under-stating chars-per-line
over-states the PR's line count and so *loosens* this ceiling, and #664 has just measured what a fix
budget that binds too early costs — a correction priced out into a regression the next round paid to
rediscover.

### what it will not do

**A derived budget is never zero.** `low_severity_fix_lines: 0` is a written value with its own
consequence — it raises the applied floor to the trigger cut — so a proportion flooring to 0 on a
very small PR would express that decision without an operator having made it, as a side effect of
the PR's size. The derived value is clamped at **1**, the smallest budget that is still a budget,
and a written `0` is left exactly where it is. This key may lower a budget; it may never raise one
or switch one off.

**A percentage with no absolute beside it bounds nothing.** At `low_severity_fix_lines: null` there
is no smaller half to take, and the percentage does not become a budget on its own — a repo that
wrote "no budget" must not get one back from a key it never touched. The round says so in
`config_notes` and names the key that would put it back in force.

**Nothing changes about which findings are on the budget, or the order they are spent in.**
Cheapest-first has no value term deliberately, and reintroducing one hands back exactly the
judgement #297 removed.

`null` is the proportional half off and the exact pre-#551 behaviour, settable from the board on its
own — which is what makes a shape decision reversible without a release.
