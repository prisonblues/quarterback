# a checkout's claim can now be released by the session that works the tree

`create-worktree` takes the issue's claim for the MACHINE, with no session on it. That part is
right — the agent that will work in the tree does not exist yet, and stamping the creating session
locked the eventual worktree agent out of its own row — but nothing ever picked the claim up
afterwards. `POST /session/end` releases the claims a SESSION took and a null session matches none
of them; `qb-reconcile` looks the holder up in `/active`, which lists leases, so a bare machine
name could never appear there and the check was structurally incapable of settling. Nine such
claims stood on one box the day this was found, three of them naming issues that had closed seven
hours earlier, and only `qb-release` by hand or the 8h fuse could end one.

The claim is now handed over rather than re-attributed. The worktree's own `CLAUDE.local.md` tells
the agent that opens the tree to re-claim the same issue from inside its session, which the board
reads as a renew by the same machine: the row keeps its id, its history and its plan item, and
gains an owner that ending the session can find. `/fix-issue` and `/review-pr` carry the same step
for the routes they cover.

### And the check that could not settle one now can

The other half of the same failure, for the claims nobody adopts. `/active` lists leases and every
lease holder carries an agent name, so a bare machine name can never appear there — not "is not
there today", cannot be. `qb-reconcile` looked one up anyway, found nothing, and explained the
absence with the one sentence that could not apply to it: that a working agent had gone quiet for
half an hour between lease renewals. Nine claims read that, every fifteen minutes, under
`complete: false`.

Three of the nine named issues that had closed seven hours earlier, and the same report already
said so a few keys away under `done_candidate`. That fact is now read across: a claim over work
GitHub reports merged or closed-as-completed is a stale claim, settled on the state of the work
rather than on who is still at a keyboard. A claim a live session holds is never promoted that
way, because an agent's last turn happens with its own issue already closed.

A checkout claim over work that is still open stays an unknown, and now says what it is — which
tree holds it, that `remove-worktree` hands it back once that tree is gone, and that its own TTL
is otherwise the only thing that ends one. Nothing here releases a claim.
