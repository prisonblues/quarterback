# a finding can be asked to earn a second seat before it becomes work

Every brake this panel has acts on a finding that has already been accepted as work: a budget
bounds what a fix pass may spend on it, a weight prices where the spending lands, a ceiling
bounds what one pass may write. None of them can ask the question that comes first — should
this have become work at all?

`review_panel.threshold_by_severity` asks it. It is a mapping of severity band to the number
of **distinct members** that must independently raise a finding before a fix pass is asked to
clear it: `{"P3": 2}` reads "a P3 one seat raised is reported, not fixed". A band the mapping
does not name needs one seat, which is what every band needed before, so `{}` is the whole off
switch.

**It ships `{}`, unset rather than off.** The evidence that corroboration predicts a real
finding is eight findings on two pull requests — the four refuted by hand on 2026-08-20 were
each single-seat and every multi-seat finding was real — and in that same table one solo
finding was genuine, while the round that produced three wrong P2s was a panel of **one**,
where every finding is solo by construction. Eight findings is an observation, not a
calibration. The instrument is already published on every round, so a repo can measure its own
precision by seat count before writing a number.

### It cannot suppress a blocker, and that is a property of the mechanism

A threshold is the only dial here that can hide a real defect: the rest decline to spend, this
one declines to look. So the bound is in code rather than in the default. A threshold may be
applied only to a severity **below `round_trigger_floor`** that is also **not `P1`/`P2`** —
`round_stop` rule 2's own bar, read from where rule 2 reads it. A repo that writes
`{"P1": 2}` gets a round that applies 1 and a `config_notes` line saying the key was ignored.

Two things fall out. A single seat finding a genuine P1 is handed to the fixer exactly as it
always was — that is the case the panel exists for, and a head count is the wrong instrument
for deciding to ignore it. And anything a threshold *can* stand down is a finding rules 1, 2
and 3 of `round_stop` already ignore, so it cannot hold a cycle open and the stop rule needed
no new parameter.

### Reported, never suppressed

A finding under its band's threshold keeps its master verdict, keeps its board row, and is
printed under its own heading with the seat count that stood it down — the disposal a
below-floor finding already gets, for the same reason: a finding that vanishes is a finding
nobody can argue with. The payload carries `below_threshold` and `seats_required` on every
finding, so an orchestrator building a fix brief can see the suppression rather than
reconstruct it from a join. A Sonar hard-gate issue is exempt at every band: it is a red
quality gate filed by a scanner, and "not enough seats agreed" is not a sentence that can be
true of one.

Settable from the board like the floors beside it — the first dial whose value is an object,
so its bands are validated and case-normalised at the settings endpoint the same way a floor
is.
