# create-worktree no longer starts the background worker unless asked

A worktree whose repo has a task worker (huey, rq or celery) used to start that worker with the app. Most worktrees are code-and-test only, and during lexray v22 one such worker ran its periodic jobs on ~4 cores of zeus, which slowed the promotion gate and the CI runners on that box (lexray#4458).

The worker is still written into the worktree's `docker-compose.yml`, under a `worker` compose profile, so no bare `docker compose up -d` starts it, including a later restart by hand. The summary marks the worker `(not started)` and prints the one command that starts it. `--with-worker`, or `worker.autostart: true` in `.worktree.json`, starts it with the app; `--no-worker` keeps it stopped whatever the config says. `autostart` must be a JSON boolean. `remove-worktree` now takes the stack down with every profile enabled, so a worker started later goes with it.
