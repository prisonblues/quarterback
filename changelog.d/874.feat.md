# heavy jobs on one host queue for memory, not for a slot count

Before this, nothing on a shared host knew how much memory the jobs already running there had
taken. lexray's test queue counted runs, and panel rounds and other repos' suites took no part in
it. On 2026-11-15 four CI runs filled zeus, and two panel rounds were killed before they produced
anything.

`heavy-slot` is a per-host queue that admits a job when its memory fits in the budget (MemTotal
minus a 12G reserve by default), checked against live MemAvailable too. Jobs are admitted first
come, first served, with an elastic grant up to a max in whole units, and the kernel releases a
reservation however its holder exits. A panel round now reserves 6G before it reads the PR, and
waits for room rather than starting into a squeeze. That protects it only from jobs that queue
too; the lexray client and the zeus runner wiring are separate changes in those repos.
