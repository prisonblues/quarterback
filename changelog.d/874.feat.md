# heavy jobs on one host queue for memory, not for a slot count

Nothing on a shared host knew how much memory the jobs already running there had taken.
lexray's test queue counted runs, and other jobs took no part in it, so on 2026-11-15 four CI
runs filled zeus twice. `heavy-slot` admits a job when its memory fits the host's budget
(MemTotal minus a 12G reserve by default, checked against live MemAvailable too), first come
first served, and the kernel releases a reservation however its holder exits.
