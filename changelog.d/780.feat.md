# the shapes an agent writes under review pressure, caught without a vendor call

Every seat on this panel is an LLM reading a diff, so the cheapest defects to detect — the ones
with a fixed shape — cost a vendor call and a judge ruling like everything else. That is the wrong
price for them, and the argument is not only about money: 128 of 201 new findings across seven PRs
were written by the fix pass answering the previous round, and no cycle has ever been recorded as
converged (0 of 27). The defects an agent writes *while it is trying to satisfy a reviewer* are not
a random sample of defects. They have a fixed shape, because the pressure that produces them is
always the same one — make the finding go away, cheaply, in a form a diff reader will accept.

**The population is the fix pass, not the pull request.** That is the whole difference between this
and a linter, and it is why it is built as a seat. A linter reports what a file contains; this
reports what the last pass wrote *in order to answer a review*, which is a far smaller set with a
far higher hit rate and a different remedy. It takes the range diff the panel already computes for
provenance, and emits nothing for a line that diff did not add. **And a fixer cannot talk it out of
a finding**, which is the property the fix-budget work is short of: a vendor seat can be persuaded
— the pass writes prose explaining why the shape is fine, the next round's seat reads that prose,
and the finding is gone without the code changing. There is no prose channel here. Rules in, diff
in, findings out.

**Ten rules, each one a flat data file with a closed key set and a match kind from a closed
vocabulary.** Placeholder bodies and broad handlers that swallow an exception or return a falsy
sentinel are P2; unfinished-work markers, narrator and numbered-step comments, unnamed lint or type
suppressions, type erasure to `Any`, pass-through wrappers and unused imports are P3. Two regex
kinds and five matchers over Python's own `ast` — Python only, and checked rather than assumed:
this repo ships no parser generator, and the sandboxed test job runs the suite under a Python
holding pytest and nothing else, where a rule needing an absent parser would not degrade to a skip
but to a collection error. Validation is strict and every failure is fatal at load — a missing
field, an unknown key, an unknown match kind, a duplicate id, an empty rules directory. Nothing is
skipped, because a rule file that does not load is an operator error about a checked-in file, and
degrading it to "that rule quietly did not run" is how a seat comes to report clean because half of
it was misspelt.

**Every rule ships a positive fixture and a false-positive fixture**, both parameterised over the
rule list, so a rule cannot land without evidence in both directions. Two anti-false-positive
devices earn their place on their own: string literals are stripped before line matching, so prose
quoting a shape does not fire on it, and the comment rules read only lines whose first token is the
comment marker. The suite also runs the seat over its own source and its own tests and requires
silence — the prose explaining a rule must not trip it.

**There is no authorship classifier and no slop score, and the suite fails the build if a rule's
text acquires one.** "Written by a model" is not a defect and is not detectable; this panel reviews
code the fleet's agents wrote almost exclusively, so a rule scoring authorship would score every
line and rank nothing. Each rule names one concrete defect and one remediation, or it does not
ship. Anything needing a judgement about intent stays with the LLM seats, which is what they are
for. Per-finding confidence is deliberately absent too: in this panel that is the corroboration
count — how many seats independently raised a defect — and it is not something one seat may declare
about itself.

**And it is now a seat.** `slop` joins the reviewer roster — selectable, nameable in `reviewers`
and on `--reviewers`, and deliberately NOT one of the LLM seats: membership of that tuple is what
hands a seat a model, a reasoning effort, a diff budget, a composed prompt and a vendor CLI, and
this one has none of them. Its config block carries `enabled` and nothing else, which is the shape
a seat with no brain takes. A round dispatches it into the same executor as everything else and its
findings join the population the judge clusters, so a defect two seats raise merges on its title
and the judge can dismiss a rule that was wrong on this diff — a cheaper answer than a confidence
field the seat declares about itself.

**It takes the fix range the round already read, and refuses to run without one.** The range a
round resolves for provenance and the surface measurement is now read once, in the setup phase,
and the seat is handed that same string — so the seat and the attribution numbers can never
describe different spans, and no round pays for a second compare. Where there is no readable range
— round 1, a branch rewritten between rounds, an API refusal — the seat does not run and the report
says why. The fallback that is always to hand is the pull request's own diff, and it is the one
thing that would make this seat wrong: on round 1 the "fix pass" is the change under review, so a
seat reading the PR diff there reports the author's work as the fixer's slop with a deterministic
matcher's authority behind it.

**Off by default across the fleet, on in this repository.** The rules were calibrated here — 383
raw hits over 252 files down to 90 after the false-positive work — and nowhere else, so the fleet
default is the conservative one and the repository that measured it asks for it in its own rules
file, with the argument and the one-key way back written beside the switch. It costs no vendor call
and no token, it is in no `escalate_on` rung and it stops nothing: still instrument-before-gate,
and what a run of real cycles is for. The import is guarded and so is the rule load, on the rule
the other optional lanes already keep — a seat that cannot load costs a round a line, never the
round. It cannot be asked a question and is not asked what it would do instead: there is no prose
channel into it or out of it, which is the property that makes it worth having.
