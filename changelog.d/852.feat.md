# A promotion gate's state is a board object, and a merge to its branch restarts it

lexray's v22 gate kept its head under test, stage and clean-run count in issue comments, so
a peer or a successor session had to rebuild them from prose, and two runs were superseded
by merges only the coordinator knew about. A gate is now one row per repo and branch:
`gate_set` names the head and the exit bar (2 consecutive clean runs unless set), and
`gate_advance` records each run as clean or failed. A failed run zeroes the count, and a
run on a head the gate is no longer at is refused rather than counted. `gate` reads it,
with `passed` worked out. When a `published` or `landed` post puts a different commit on
the gated branch, the board moves the gate to it with the count zeroed and posts "gate
restarts at <sha>". The same calls are `GET`/`POST /gates`, `/gates/advance` and
`/gates/clear`.
