# a payload key the board silently drops now fails the suite instead of being noticed months later

`ReviewIn` is declared `populate_by_name=True` with no `extra=`, so pydantic's
default `extra="ignore"` applies: a top-level key the panel sends and the model
does not name is discarded without a word, without a log line and without a 422.
That has now happened five times — `head_sha`, `unread_files`, the provenance
pair, `converged` (#626), and `review_panel`, which this release stores. Each was
found by a human noticing a number was missing, months apart, and each of the
first four was fixed as an instance rather than as a class.

`tests/test_payload_key_drift.py` closes the class. It reads every top-level key
the panel's four payload exits carry out of `harness/loops/panel.py` and compares
them against `ReviewIn`'s field names **and validation aliases** — the aliases
because the panel calls the repo slug `github` and the PR subject `title`. What
is left over is what ingest drops, and it is held against a list of the
twenty-five keys that are dropped **on purpose**.

So a key added to the payload now fails the suite on the commit that adds it, and
the only way past is to name it: as a field on `ReviewIn`, as a key the panel
stops sending, or as a line on that list with the reason. None of those is
silence, which is the whole of the fix.

The list is **written out by hand and not computed**. A computed one would pass
forever — which is the property every version of this check that was proposed and
not written would have had.

Two failure modes of the check itself are covered rather than assumed. It is read
with `ast` and not by importing the panel, because `harness/loops` installs
without `app/` beside it and a check that skips when an import fails is a check
that never runs anywhere (the lesson of `test_post_type_drift.py`). And because a
static scan that matched nothing would compare two empty sets and pass, one test
pins a floor on what the scan found and another puts an unknown key in front of
the detector and asserts it is reported.

### `review_panel` — the dials a round ran under, stored

One of the twenty-six dropped keys came off the list rather than going onto it.

`review_panel` is the #165/#297 dial set **as the round applied it** — a repo
whose `fix_severity_floor` was rejected reads here the floor that actually ran.
It is also the policy `converged` was decided under: two of that flag's conjuncts
are cut at `cleared_floor`, which is `round_trigger_floor` or
`fix_severity_floor` depending on whether a line budget is in force. All three
are in this object and none of them was on the row, so a reader handed a stored
`converged` could not check it against anything.

This does not make #626's column unnecessary — a stored answer still beats a
reconstruction, and `m6bc45ff1` says at length why a board-side derivation would
be free to disagree with the panel about the same round. It makes the stored
answer **auditable**, which is a different thing and was not previously possible.

Migration `mc57fb9ba`: nullable JSONB, no server default, no backfill, no CHECK,
no index. NULL is "the panel did not say", which is every row recorded before it
and — permanently, by design — every skip and every pre-flight refusal, because
those paths resolve a review policy and never apply one. A backfill would have to
attribute today's dials to rounds that ran under whatever was written months ago,
which is the #305 incident manufactured rather than merely unanswerable.

Stored **opaquely**. Nothing on this board reads a dial name out of it or coerces
a dial value: `app/api/dials.py` argues that a second place that knew what
`review_panel.max_rounds` meant is the drift #305 exists to end, and a dial the
panel adds is stored here without anyone editing a tuple in this repository.
What ingest does refuse is shape and size — a value that is not an object, and an
object over `MAX_DIALS_CHARS` — and both refuse the **whole** object rather than
trimming it, because half a dial set is not a smaller policy but one no round ran
under. Either refusal is named back to the sender, under
`unreadable_fields` and `review_panel_dropped` respectively; the two are separate
signals because a wrong shape and an oversized object are different sender faults
wanting different fixes.

It rides on `GET /review/{id}`, beside the verdict it produced, and deliberately
not on `GET /reviews` — one run's policy is a fair payload and a page of five
hundred is a config dump, on the rule `unread_files` already follows.
