# the fix brief says a finding is a hypothesis, at the top where it is read

The brief handed a fixer a list of findings and an instruction to clear them. That a finding might
not survive contact with the current code was said — in a section several screens further up, as
prose about how to record an outcome — and a contract stated where the work is not is read as
background. Worse, the list itself was often a *patch*: a diff, a rewritten function, a "change X
on line N to Y". A finding delivered as a patch is a fix already chosen, and the fixer's only
remaining move is to apply it, which is how a symptom raised at one line becomes an edit across the
class — and the class-wide edit is where the next round's findings come from.

**A fixed preamble now sits at the head of the finding list, verbatim.** It says the findings are
hypotheses to verify against the current code before anything changes, that ones no longer valid
are skipped with a brief reason, that each is an outcome rather than a patch, and that changes stay
minimal and get validated. It is stamped immediately above the first finding rather than anywhere
else in the brief, and it travels: whoever writes the brief puts it above the list they hand on,
and the fixer puts it above each group agent's list when the work fans out. A group agent reads
nothing but the brief written for it, so without the preamble a group brief is a list of patches to
apply — the exact shape that turns one line's symptom into an edit across that group's files.

**Findings are handed over as outcomes, not patches.** What must end up true, not which keystrokes
get there; the fixer is the one reading the surrounding code and decides the shape. Where a seat
wrote a patch into its finding, the brief relays the end condition it was aiming at. This is the
`narrowed` argument one step earlier in the pipeline — `narrowed` bounds a fix *after* the finding
has already been written as a patch, and reading the finding as an outcome is what stops it being
written that way at all.

**A finding this round is not asking to be cleared does not go into the brief at all** — not pasted
under a caveat, not listed for context, not mentioned in passing. The below-floor list and the
single-seat list were already excluded by name; the rule is now general, and it is stated as a
rule: an excluded finding is not a finding left unfixed, it is one this round did not ask for, and
pasting it with a note re-opens a judgement already made in front of the one reader whose entire
brief is to clear the list in front of it. Those findings are still recorded from the round's
payload, without the fixer ever seeing them.

**The preamble is worth more on a panel round, not less.** A panel finding arrives seat-verified
and judge-confirmed, and that provenance is precisely what stops a fixer checking it.

Prompt-only. No dial, no new field, and nothing in the payload changes.
