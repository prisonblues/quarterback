# the merge gate can read a severity floor, so a repo that raised one can finish a cycle

`preland.py` decides whether a pull request may be merged. Grep it for `severity`,
`floor`, `P2` or `P3` before this change and there are no matches: the clause was
`elif confirmed: HOLD`, so any nonzero judge-confirmed count was a reason to hold,
whatever the findings were.

That contradicts `review_panel.fix_severity_floor`, whose entire content is that
findings below it are **reported and not fixed here** (#165). The panel prints them
under their own heading, `round_stop` hands them to nobody, and the merge gate then
held the PR on them anyway. The two halves of one system disagreed about what a
below-floor finding means, and the practical effect is that a repo running a raised
floor could essentially never reach READY — a round asked to find problems almost
always finds a P3, and P4 has no bottom, which is the observation the floor was
built on in the first place.

Measured on lexray#1631, a seven-file migration change. Round 2 stopped with
`handed_to: "nobody"` and this verdict: *11 finding(s) are outstanding and every one
is under the P2 cleared floor: the repo's own policy is that these are reported and
not fixed here, so nothing is handed on.* Every one of the eleven was recorded
`deferred` on the board, two of them carrying GitHub issues. Seven of eight preland
checks passed; the eighth returned HOLD on "11 judge-confirmed finding(s) are
unresolved", and no amount of outcome recording reduced it.

### The answer already existed and had no channel

`round_stop.outstanding` has carried `fixable`, `below_floor` and `escalated` as
separate lists since #42, with `handed_to` as the round's own verdict on whether
anything is owed. `qb record-review` POSTs the whole block. `ReviewIn` is declared
`populate_by_name=True` with no `extra=`, so pydantic's default `extra="ignore"`
applied and ingest dropped it — the same silent drop this file records for
`head_sha`, `unread_files`, the provenance pair and `converged` (`m6bc45ff1`), in
the same module, for the same reason. The severity split exists on every round the
panel has ever run and was recoverable from none of them.

So `review_runs` grows two columns. `outstanding_counts` is the **length** of each
of the five lists, and `handed_to` is the one-word verdict. Nothing on the board
decides which finding is below which floor: the floors are repo dials it holds as
opaque JSON and does not interpret, and a board-side split would be a second reading
of the policy that produced the verdict stored beside it — `m6bc45ff1`'s argument for
`converged`, and `app/api/dials.py`'s at length. Lengths rather than a `counts` block
sent beside the lists, because `len()` of a list cannot disagree with that list while
a sibling tally can.

`preland` then HOLDs on `fixable + escalated` and **warns** on `below_floor`.

### Three ways this could have become a laxer gate, and none of them is taken

**Unknown is still unknown.** The clause above this one is untouched, comment
included: a round that recorded no confirmed count HOLDs and never reaches the new
one. A round that recorded no disposal — every producer older than #42, and every
block the board refused — is held on the raw confirmed count exactly as before.
Silence buys nothing, in either clause. There is no backfill for the same reason:
the split cannot be guessed from a count that does not contain it, and every missing
input would read as "nothing outstanding", which is the flattering direction on the
one field that decides whether a PR may merge.

**Escalated findings block at any severity.** They are open questions a human owes an
answer on (#221), so they are added to `fixable` rather than compared against a floor.
The sum is sound rather than hopeful: `round_stop` removes the escalated and narrowed
keys before splitting the rest at the floor, so the three sets are disjoint by
construction, and `harness/loops/tests/test_panel_outstanding.py` pins it.

**Nothing is subtracted from anything.** The obvious repair — take a below-floor count
off `n_confirmed` — is the one thing this must not do, on two counts. The populations
differ: `confirmed` is every confirmed finding on the round, while the disposal is
computed over that set minus the keys an outcome already cleared, minus the escalation
register, minus what a fix pass narrowed, so a difference between them is a number
about neither. And an escalated finding can be below the floor, so a subtraction is
the shape in which one quietly stops counting.

Below-floor findings are warned about rather than dropped. The repo's policy is that
they are not this round's work; it is not that they do not exist, and a payload that
read clean by saying nothing about eleven of them would be the same silence one
direction over. A disposal that arrives without one of the three buckets a gate reads
is refused whole and named back to the sender under `outstanding_dropped`, on the same
rule: a block short one bucket looks complete and reads as a zero in it.

`ReviewIn.round_stop.outstanding` is typed `Any` rather than `dict`, on this module's
standing rule that a payload is never refused over one field — a hand-rolled caller
sending `outstanding: []` would otherwise lose its findings, its scorecards and its
accounts to a 422.

### one more, found by a second opinion on this PR rather than on the code it fixes

`narrowed` and `declined` are not required, so a producer sending `narrowed: 5` —
a count where the contract is keys — had the bucket quietly omitted from a
disposal the response then reported as stored. A stored disposal missing a key
means "the producer sent none", so that filed a value this board had refused under
the shape a #42-era producer legitimately sends: the absent-versus-refused collapse
this module argues at length one field over. The four readable buckets are still
stored — refusing a whole disposal over two numbers no gate consults is the wrong
trade — and the drop is now named. `_outstanding_or_none` therefore has three
readings rather than two: stored whole, stored without the buckets its reason
names, and refused entire.
