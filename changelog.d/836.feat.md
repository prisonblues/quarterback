# review loops converge: a class ledger, a two-strike rule and a round budget

Review rounds had no closed list to check against. The panel had brakes, but its
target was always "find defects in this diff", so every round found the next path to
a defect an earlier round had already found. The hand-rolled `codex exec` loops in
`/fix-issue` and the epic coordinators had no brakes at all. Lex-Ray v22 spent 107
Codex rounds this way. Every loop that did not converge ended only when somebody
noticed by hand that its findings were one class, and fixed the class instead of the
path.

### What changed

- **Class ledger** (`panel_classes.py`, `panel.py --class-ledger`). Each finding is
  recorded against a defect class with its invariant, enforcement and guard test.
  Rounds after the first are briefed from the ledger: verify the invariants
  everywhere, and report only violations and genuinely new classes. `--class-wave`
  reads other PRs' ledgers from the same wave.
- **Two strikes.** A class seen on its second path is owed a fix that makes it
  impossible by construction, and "fix this path too" is refused (exit 5).
- **Round budget.** A round converges when it records no new class. After
  `review_panel.class_ledger.rounds` (3) rounds without that, the next round is
  refused and the owner decides between the structural options listed.
- **Whole classes.** Every reviewer is now asked to name each finding's class and to
  list every instance and every path that reaches it.
- **`/codex-round`** (`codex_round.py`) replaces the hand-rolled Codex loops. One
  Codex seat, no judge, with the ledger, the two-strike rule and the budget. It may
  run the touched tests and code in the builder's own worktree under codex's
  `workspace-write` sandbox, and is checked for leaving the tree changed.
  `--no-exec` gives the read-only seat. `--shard` splits the read into
  data/API/concurrency (one seat at a time when they run code); `--design` reviews
  a design note. An unreadable ledger is refused (exit 3), never read as empty.
- **Brief hygiene.** `/fix-issue` gains a design round for invariant-heavy work and
  a production-constraints check. `/fix-issue`, `/fix-issue-here` and the fixer
  brief now require autospecced mocks and touched test files run in full, DB tests
  included, and keep heavy compute off the dev box. `/epic` gains a wave-kickoff
  checklist (design-first list, migration-head queue, one owner per class).
