# a context reset is now told apart from a resume, and says so

`qb-hook` never read `SessionStart`'s `source`. `grep -n source` over the script found only
comments, so every start looked alike — including the two that are opposites. A `clear` is a
conversation that remembers nothing of the one before it and must not go on holding its work;
a `resume` is the same conversation continuing, and dropping its claims would be the same bug
pointing the other way. The backstop that ends a superseded conversation therefore recorded
`superseded` for all of them, which says only that something else is here now.

It now records `context_reset` when Claude Code says the previous conversation was cleared,
and `superseded` for everything else — `compact` and `fork` both carry memory forward, and an
older Claude Code sends no source at all. A resume is refused twice over: by the source, and
because a resume reuses the session id.

### What this does not fix

**The claims themselves, in the case that matters.** `/session/end` releases a session's
claims by session key, and the key stamped on a claim taken through the MCP server is whatever
session id that process was spawned with — it is never respawned, so after a `/clear` it stops
moving. The release therefore reaches the first reset in a terminal and no later one. Closing
that needs the two halves of an agent to agree on one key after the session id has moved,
which is #146, and the two values in the environment that look like they could carry it do
not: `CLAUDE_CODE_MESSAGING_SOCKET` is inherited verbatim by a nested `claude -p`, so it names
the outermost terminal rather than this one, and `CLAUDE_CODE_SESSION_ID` is injected per
spawn rather than frozen at launch. Two live agents sharing a key is worse than one agent
holding two: they would share the supersede record, and the next start in either would end the
other's session and hand back the claims it is still working.

**And the premise both issues were filed on is stale.** They say a seat pins its identity with
`QUARTERBACK_INSTANCE`, so #146's split cannot happen to a seat and #263's is the seat's to
suffer. `qb-seats` unsets that variable and puts nothing in its place (#540), so nothing on
this fleet sets one: every session keys on its own session-id prefix, seats included.
