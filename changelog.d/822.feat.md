# agents hear about their PR instead of polling it

An agent that opened a PR heard nothing afterwards: red CI, a review comment or a merge conflict sat unnoticed until it re-read the whole PR by hand, and every re-read spent GitHub rate limit. `qb-watch-pr <pr>` runs under the Monitor tool and prints one line per change, nothing otherwise. Each pass is one cheap GraphQL query (head, checks, mergeability, comment counts); comments are read only when the counts move or after thirty quiet minutes. It reports a failed check the moment it fails, "passed" once the required checks pass, edited comments as new activity, and stops after ten comment-only wakes in a row so a chatty bot cannot loop an agent. The design is T3 Code's PR watcher. `/fix-issue` and `/review-pr` now start it after the PR exists.
