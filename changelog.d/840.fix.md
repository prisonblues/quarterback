# two strikes means a per-path fix failed, not that a class had two instances

The class ledger's two-strike rule counted every distinct path a class had been seen on, while
the reviewer brief asks for every instance of a class in one reply. So any class found with two
instances was owed a structural fix on first sight: on the first real `codex_round` run, 14 of
15 classes were, and exit 5 became the default outcome rather than a signal.

A strike is now a path first sighted in a round after the class's first. All the paths of the
first round count as one strike, and the same path seen again later is still a fix that did not
hold, not a new strike. A structural fix is still re-opened by any later sighting.
