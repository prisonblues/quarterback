# a review round says which PR it is on, and the dashboard stops having to guess

`GET /active` carries no work reference at all. A lease has `repo`, `branch`, `title`, `state` and
`stage`, and nothing anywhere on it names an issue or a pull request — so an agent three hours into
reviewing `lexray#1780` read, on every fleet surface, exactly like one that had just opened the
repo.

Measured on this board while #253 was open: **five live agents, three of them reviewing, and
`GET /claims` returning `[]`**. The dashboard's AGENTS rows read `master`, `test` and `Panel review
PR rework` — a branch name that names no work, a branch name shared by every seat on the box, and a
prompt title. The one row that was on a real branch was a panel reviewer working in
`/tmp/panel-claude-cnawzmey/cwd`, which is #601 arriving in the same cell.

The obvious repair is a new field — have the agent report what it is on — and it is the wrong one.
#253's rule, from #229 and #172, is that the event has to be **derived from an action that already
happens**, never from a second declaration somebody must remember to make; #172 puts it as
*"enforcement is in hooks and tools, not agent co-operation"*. A field an LLM fills in by brief is
the same class of thing as the prompt title already in that cell, and #157 measured what those are
worth: 26% of auto-claimed statuses were not work at all, one of them the reviewer's own system
prompt.

## the round's start was already an observable event

#253's table names this case and its observation point: *"start reviewing a PR — `panel.py` run
start, it already POSTs at the end, so it knows the PR and round"*. A panel has always recorded
itself at the **end** of a round, which is the moment the fact stops being useful for
coordination.

`panel.py` now takes the `pr` claim where it dispatches its seats, and releases it when the round
ends. That line rather than `main()`: everything above it — the merge gate (#271), the cycle-ended
gate (#617), the pre-flight verdict (#138), the CI read, the spend ceiling — could still refuse the
round, and a claim taken before them would record work that never ran.

It never gates. Every refusal is a line in `config_notes`, which is the channel that already
carries a board write that did not land, and which `--post` publishes. That includes the case where
somebody else holds the PR: two panels on one PR is spend twice and worth a line, and stopping one
is not this function's call. It goes through `qb-claim` rather than a POST, for the reason
`record_run` gives about which board a machine belongs to being site configuration — and so the key
is derived by the board (#172) rather than composed by a third party.

The TTL is three hours against `qb-claim`'s eight-hour default. The claim is handed back at the end
of the round, so the TTL is not a duration — it is the fuse for the case where the release never
runs, and what it has to outlast is the slowest round anybody has measured (20-40 minutes here),
not the working day. #608 is the complaint that a work claim is an 8h fuse the agent burning it
cannot renew; a claim that outlives its work is #135.

## the join was broken in a way the empty board was hiding

Turning the data on found the other half, and it is the bigger one. `POST /claim`
records **the machine** as an ordinary claim's holder — `holder: "daedalus"`, with the
session in its own field — and only a session-owned claim (the plan's, v2.39) records
`daedalus/sable-dune`. `agent_rows` indexed claims by holder and asked for
`agent["holder"]`, so it matched plan claims and nothing else: **every `qb-claim issue`
and `qb-claim pr` on the fleet** — the two an agent actually takes when it picks up work
— fell through to a CLAIM-ONLY row reading `machine`, one line away from the agent
holding it, whose own row said `main`. Both halves of the answer were on the screen, one
row apart, and nothing joined them.

Measured by taking one: claim `415c4b02` on `prisonblues/quarterback#253`, holder
`daedalus`, session `ce024170…`, taken by the agent the board was calling
`daedalus/sable-dune`, drawn as two rows.

Claims are now indexed by session where they name one and by holder where they do not,
and `_claims_of` asks in that order — session first because it is the exact identity: a
machine runs several agents at once and they all authenticate as that machine, so an
ordinary claim's holder cannot say which of them took it and its session can. The holder
lookup stays for the claims that name no session at all, which is `create-worktree`
taking one on behalf of a worktree before the agent that will use it exists.

Two consequences that had to be handled with it:

- **A claim is drawn once.** The "is this already on a row" test read holders, and a
  machine-held claim joined onto an agent row has a holder no agent has — so it would
  have been drawn a second time, reintroducing the duplicate as the fix for it.
- **`machine` stopped meaning two things.** The CLAIM-ONLY state asked whether the
  HOLDER named an agent. A machine-held claim carrying a session named one too, so
  presence not listing it means that agent has finished — `gone`, not "nobody ever
  said". Only a claim naming neither is `machine` now, and `create-worktree`'s
  pre-agent claim is the case that genuinely is. Presence is asked of the session as
  well, so a live agent whose claim this pane's scope hid still reads `elsewhere`
  rather than as abandoned work (#176).

## the dashboard was never the missing half

`qbdata._agent_row` has preferred a claim over the prompt title since AGENTS was three panels
(#589). It had nothing to join, because nothing on the review path claimed anything — so the cell
fell through to `title or branch` on every row, every time, and looked like a dashboard that could
not show the number rather than a fleet that had never recorded it.

Two rendering fixes fall out of turning the data on:

**The ref goes in front of the words, not instead of them.** The cell held one or the other, so it
answered *which PR is this?* or *what is this agent up to?* and never both. It now reads
`PR#1780 · Panel review PR rework`. A prefix rather than a column of its own: the narrow dash is 69
columns, this table already spends 13 on `who`, and a column costs that width on every row
including the ones with nothing to say. A plan or item claim keeps its own words, because
`claim_label` has already resolved those keys to the item's title and a prefix would print the same
sentence twice. The round number is not in the cell — it is in the `stage` column beside it.

**A PR's claim key stops reading as a storage detail.** `!` separates repo from number in a PR's
key because an issue and a PR can share a number (`app/claimkey.py`), and the scope trim left a
bare `!1780` — the right PR in a spelling nothing else on the screen uses. It renders `PR#1780`
now, which is `plan_ref`'s spelling for the same PR one table over (#272), so a PR an agent holds
and a PR the plan ranks read alike.

## and the suite cannot claim a live PR

`conftest.pr_claims` stubs both halves, autouse and unconditional, on `recorded_runs`' argument
exactly: `qb-claim` resolves the board out of this host's site config and is on the PATH of every
enrolled workstation, while the nix sandbox carries neither — so without the guard the suite would
be quietly correct on the one box nobody develops on. It is worse than the record it copies in one
way worth stating: a spurious run on the board is bad data, and a spurious claim is bad data that
**refuses somebody**, since `create-worktree --require-claim` and the plan's pickup gate both stop
for one.
