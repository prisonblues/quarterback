# a local-only repository is back on the collision index

`GET /active` is the call every CLAUDE.md on the fleet tells an agent to make before starting
work, and #714 fixed it answering "coast is clear" about the wrong repository. Part of that fix
was the write path: a checkout with no origin remote stopped reporting a repo at all, because the
panel's review seats run in a `git init` under `/tmp` and the old directory-basename fallback put
live agents on the board in a repository called `cwd`.

"No origin" is not only that sandbox. An ordinary local-only repository — never pushed anywhere,
two agents, two worktrees — wrote `repo: NULL` on both leases, and a repo-scoped read cannot match
NULL, so `active(repo="<name>")` answered a clean board while two agents were live in it. The same
false clean, through the other half of the same field. It was also the opposite of the rule
`/active` applies one function away, where a sub-agent whose parent cannot be placed is KEPT,
because on a collision index "unknown" must not be representable as a clean answer.

The suppression is now declared rather than inferred. `panel_seats.run_cli` exports `QB_SANDBOX=1`
around every seat CLI, and `qb-hook` — which runs inside each seat, since the lifecycle hooks are
configured per user rather than per repo — goes silent only when it sees it. Everything else keeps
the bare directory name, which the board's reads already accept (`app.repomatch.name_clause`):
there, only the *identity* is unavailable, not the grouping.

The name that comes back is the **repository's** directory, not the worktree's, which is what makes
it an answer two agents can share. The scenario in the report is one local-only repo with two
agents in two worktrees, and `create-worktree` names those `<repo>-<branch>` — so the obvious
`--show-toplevel` would report `quarterback-fix-issue-721` and `quarterback-feat-issue-9`, two
repositories on the collision index where there is one, each invisible to a question asked under
the other's name. Reporting *a* name is not the fix; reporting the name the other agent would use
is. `--git-common-dir` is the one path every worktree of a repo agrees about, resolved with `cd` and
`pwd` rather than `--path-format=absolute` — that flag arrived in git 2.31, and the only thing an
older git could have fallen back to is the per-worktree name this is here to stop reporting. A
correctness dependency on a version, failing silently and passing on the box that tested it, is not
a fallback worth having.

The hook could not have decided this for itself. A fresh `git init` and a never-pushed repository
of ten years' commits differ in nothing it can see — not the remote, not a temp-dir prefix (a
worktree under `/tmp` is legitimate), not the branch name. The process that created the directory
is the only thing that knows, so it is the thing that says. The flag governs the fallback and
nothing else: a seat that somehow ran in a checkout with a real origin still reports it, so
exporting one variable cannot blind an agent that has a genuine repo identity.

**And the index question the same review raised is measured rather than guessed.** Since #714 the
repo predicate goes through `lower(substring(rtrim(...)))`, which `ix_leases_repo` cannot serve,
and the model's comment claimed the repo predicate "has never been the selective one". On a
synthetic table shaped like this one — leases are never deleted, so historic rows plus the twenty
or so the fleet holds live at any moment — at a million rows:

| index available | exec |
|---|---|
| today's (parallel seq scan) | 44 ms |
| the pre-#714 exact match, on `ix_leases_repo` | 180 ms |
| a functional index on the fold, alone | 260 ms |
| a partial index on the live set | 0.14 ms |

Both obvious repairs are slower than the scan they replace, for one reason: a repository selects a
fifth of the table and five of those rows are live. No migration ships here — 100,000 rows is 17
months of this fleet's observed session rate and answers in 9.7 ms — but the answer is now written
down beside the index, so whoever does find it slow need not re-derive it.
