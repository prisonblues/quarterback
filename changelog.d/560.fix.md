# a premise declared after its own fix pass is now recorded as one

The futility brake gets its whole value from running before the patch: `panel.py --premise` fires on the FIRST declaration that answers `--premise-decidable no`, and exit 4 means *do not write the fix*. Both that design and the fixer's brief assume the fixer is a separate agent an orchestrator briefs, so there is a moment between "decide the premise" and "start editing" for the brake to occupy. `panel-review-pr.md` recommends the configuration where that moment does not exist — with more than one PR, the per-PR agent runs the panel and then fixes, with nobody to brief — and there the premise gets declared against the round it followed, once the pass is written, committed and pushed. It still takes its veto on the next round, which is the late half; the early half, the only reason it fires on the first declaration, is unavailable.

Nothing could tell the two apart. An undeclared-then-declared pass and a declared-then-written pass produced byte-identical register entries, so a cycle where the brake was an annotation read exactly like one where it was a brake. On the cycle this was found on, the orchestrator gave the fixer no register path at all — `--premise` was uncallable during the fix pass — and the only reason anyone knows is that the fixer said so rather than inventing a path.

Each declaration now carries two readings of the tree it was made from: the commit that tree was sitting on, and whether that tree already had uncommitted changes to tracked files in it. `--premise` reads both itself, in the directory the declaration is made from; neither is a flag, on the same rule that makes a `decidable: no` sticky — a fixer asked to supply the evidence against itself can supply the answer it wishes it had, and in worktree mode the repo's canonical checkout is not the tree the patch lands in. A round then names two shapes in `config_notes`. A declaration stamped with the head of a later round was made once the fix pass it explains was already committed and pushed. A declaration stamped with its own round's head, from a tree that was already edited, was made once that pass had been written but not yet committed — and that is the ordinary shape of a fix pass, which edits and then commits, so it never moves `HEAD` and the commit ids alone cannot see it at all.

It identifies positively or says nothing. A stamp matching no round's head — an unpushed local commit, a rebase, a declaration run from the wrong directory — is left alone, because a check that accuses an honest fixer over ordinary history is one an orchestrator learns to skip past. There is no field anywhere that records a declaration as having been made in order: "nobody looked" and "nobody had edited anything" are kept apart, and only the accusation is ever made. And it is evidence rather than a rung. A stop taken here would be the late half again, and what was missing was never another way to end a cycle.

**What it does not do**, because the first cut of this said otherwise. It detects the ordering slipping, not an actor arranging for the slip not to show. Both readings come out of the directory `--premise` was run in, so a declaration made from a clean sibling checkout, one made after a `git stash`, or one made after committing locally and before pushing all read as honest — as does a fix pass whose entire output is new files nothing has staged yet. That is #622, every brake on the fix pass being measured by the actor it constrains, and no stamp closes it. What is closed is the accident #560 was opened on: an orchestrator that is also its own fixer, declaring in its own patch tree, after the pass, with nothing recording the order.

`round_stop.premises` also says whether the round was handed a register at all. Without that, a cycle that never wired one and a cycle whose fixer skipped a declaration produce the same `undeclared_rounds` list — and the first is the one that actually happened. `wired: false` with rounds listed is a cycle whose reader was not even pointed at a register. It says nothing about whether the fixer was given that path or could write it — the round and the fix pass are separate invocations, and `declared` is the field that says somebody reached the register.

The two briefs say the rest. Where the orchestrator is also the fixer, the declaration belongs after reading `round_stop` and before the first edit, the register path is the agent's own to choose because nobody is going to hand it one, and the same path goes to every round's `--premise-file` — a register the round cannot read counts nothing.
