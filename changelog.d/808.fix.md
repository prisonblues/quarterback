# remove-worktree no longer reports a teardown that removed nothing as complete

`remove-worktree` resolves the repository from the shell's current checkout, and the branch
name says nothing about which repo it belongs to. Run from the wrong checkout, it found nothing
at every one of its eight steps and still printed "Cleanup complete", while the real worktree
stayed registered and on disk, with its containers up, its database present and its board claim
held.

Each step now records what it removed. When no step that ran removed anything and none warned,
the teardown exits 2 and names the repository it searched. A tree deleted by hand still has its
registration, branch, port entry, containers and claim cleaned up. Steps that used to print a
note and let the summary say "complete" now record warnings: a directory the delete could not
remove, a registration that would not prune, a branch that could not be deleted, an nginx block
that could not be removed, was removed but not reloaded, or had no nginx container to reload
it, a port file that could not be rewritten, and a claim answer that could not be read. nginx
is no longer restarted when no block was removed.
