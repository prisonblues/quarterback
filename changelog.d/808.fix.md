# remove-worktree no longer reports a teardown that removed nothing as complete

`remove-worktree` resolves the repository from the shell's current checkout, and the branch
name says nothing about which repo it belongs to. Run from the wrong checkout, it found nothing
at every one of its eight steps and still printed "Cleanup complete", while the real worktree
stayed registered and on disk, with its containers up, its database present and its board claim
held.

It now exits 2 and names the repository it searched when nothing of the worktree is there: no
directory, no registration, no branch, no port entry and no nginx block. A tree deleted by hand
still has its leftovers cleaned. Three steps that used to print a note and then let the summary
say "complete" now record warnings: a directory the delete could not remove, a branch that
could not be deleted, and an nginx that did not restart.
