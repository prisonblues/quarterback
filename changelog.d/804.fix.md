# the teardown backup stops archiving what provisioning installed

`remove-worktree` wrote a tarball of every ignored file it found, which on a repo declaring
`copies` is mostly what `create-worktree` had just put there. Measured on one box: 133
archives, 8.3 GB, and 110 MB of every 112 MB lexray tarball was `apps/models` — spaCy and
MiniLM weights, byte-identical to the main checkout's copy, re-gzipped on every teardown,
around the few KB of `.env` and `CLAUDE.local.md` anybody would actually open.

The repo's own `.worktree.json` already says which paths those are. `copies` and
`gitignore_additions` are now excluded on the same terms the build-cache filter uses —
**ignored entries only**, so a tracked edit under one of those paths is archived like any
other — and the teardown names what it is leaving out. A `copies` path the main checkout no
longer holds is still archived: the worktree's may be the last copy on the disk.
`env.copy_from` is deliberately not excluded, because `.env` carries the worktree's own
port and database name and is the file people hand-edit.
