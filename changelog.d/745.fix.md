# the guard refused one way to empty a worktree and left the wider one open

The shared-tree guard covered git's "restore this path from that ref" command and its
stash pushes, and did not cover `checkout-index`, which restores **every tracked file**
from the index. The classifier said so in a comment: both `checkout-index -f` and
`read-tree --reset -u` had been considered and dropped, on the grounds that they were real
forms nobody had ever actually run.

On 2026-09-04 one of them ran. A sub-agent doing the red/green step of `/fix-issue` found
the ref-restore form refused, reached for `git checkout-index -a -f` instead, and rewrote
every tracked file in its worktree from the index — reverting finished documentation edits
and truncating a module it had just written. Nothing said a word, because that command is
silent when it succeeds. It recovered because the agent happened to look.

The premise was what failed, not the reasoning. "Nobody reaches for it" was never a claim
about the command; it was a claim about the caller, and the caller is somebody who has just
been refused and is looking for the next thing that does the same job. Refusing the rung
above does not remove the reach — it aims it. And the rung below was the worse one: `-a`
names no path, so the blast radius is the whole worktree rather than one file, and there is
no ref, so it does not read as a discard to anyone reviewing it.

### What is refused now

`checkout-index` with `-f`/`--force` or `-a`/`--all`, and `read-tree --reset -u`. The
second has not happened; it is the next rung down from the one that has, and guarding a
family one incident at a time is how the family gets walked one incident at a time.

Both halves of the `read-tree` rule are required. `--reset` without `-u` rewrites the index
and stops there, and index-only damage is consistently not this harm — `reset HEAD~1` and
`restore --staged` are not refused for the same reason. `-u` without `--reset` is not a
command git accepts at all.

Nothing wider went in. `env`, `sudo`, a `$VAR` target and a `cd` in an earlier clause stay
on the documented not-chased list: this is a tripwire for an accident, not a gate against
an adversary, and an unbounded list of spellings is what chasing bypasses produces.

### The way out is part of the guard

A refusal that names no working alternative does not stop the caller, it moves it one rung
down — which is precisely what happened. So the refusal now spells out the red/green undo
rather than alluding to it: capture a patch over the paths you name, `git apply -R` to take
the change out, `git apply` to put it back, and `git show <ref>:<path>` piped through `tee`
when you want exactly one file. Verified end to end over a change spanning a part-staged
tracked edit and a brand-new file.
