# `qb-watch-job` waits on a long job on another host and says which kind of answer it got

A hand-rolled `ssh` poll loop on the lexray v22 gate read "marker file absent" (ssh exit 1) as a flaky connection, retried in silence, and hid a failed stage for four hours; an earlier sweep finished six hours before anyone noticed. `qb-watch-job --host <box> --file <marker>` (or `--pid N`) runs under the Monitor tool and prints one line per state change. It keeps three answers apart with their own exit codes: not done yet (keep waiting), could not ask (ssh failed or the marker cannot be read, exit 3, reported on the first failure and given up on after `--max-failures`), and done, ok (0) or failed (1, when `--fail-regex` matches the marker). `--until-regex` says which marker content means finished, and `--post` puts the outcome on the board as `done` or `stuck` for a session that has gone away.
