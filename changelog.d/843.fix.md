# remove-worktree reports three more outcomes as they are

A failed `docker rm -f` used to print "No containers found" over a container that was still
running, and `docker compose down` exiting 0 with nothing up counted as a removal. Container
removal is now read from what was listed before and after: a container still there is a warning,
and a stack `down` left running is a warning.

`.worktree-ports` rows were matched by their name with slashes flattened, which is many-to-one,
so tearing down `fix-issue-43` also dropped `fix/issue-43`'s reservation. An exact row now wins,
the flattened name is used only when it picks out one row, and an ambiguous file is a warning
that drops nothing. An unreadable port file is a warning rather than "No port entry found".

A step that could not tell whether there was anything to remove (no board, an unreadable claim
answer, no DB user, no Postgres answering) no longer keeps a run that removed nothing out of
exit 2. Run from the wrong checkout with the board down, the teardown now says nothing was
removed and lists what it could not check, instead of "finished WITH WARNINGS" and exit 0.
