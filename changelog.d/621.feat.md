# a review round can end because there is nothing left that blocks

A panel cycle could not converge, and the reason was mechanical rather than
cultural. `round_stop` went again while ANY finding an earlier round had raised
was still outstanding at or above the fix floor — so a single unfixed P3 kept a
cycle alive indefinitely, and the only move available to the fixer was to write
lines. Lines are what the next round reads. On `prisonblues/lexray#1780` that
loop ran five rounds with to-fix counts of 5 → 7 → 12, both of its late P1s
written by the fix pass immediately before them, and the change grew from 18
files to 27 — ten of which were pulled in by fix passes rather than by the work.

What changes is which findings a round must clear, and what a fix pass is
allowed to be.

### Only what blocks keeps a cycle going

A repeated finding now goes again only if it would have triggered a round in the
first place — `round_trigger_floor`, not `fix_severity_floor`. A sub-trigger
finding the budget could not pay for is reported and named, never silently
folded into "dry". P1/P2 and SonarCloud hard-gate issues are unchanged.

### A fixer can answer a finding narrowly

`narrowed` is a fifth recorded outcome: the finding is real, this pass fixed it
at the point it was raised, and the general form is not this pass's work. It
CLEARS, so the round does not go again for it. It requires a note — the general
form it did not take — at the API and at the database boundary both. Until now
the vocabulary offered three ways to decline a finding and none to answer it
partially, so the maximal fix was the only one that satisfied the brief.

### The cycle remembers that it stopped

A panel run on a pull request whose last round ended terminally is refused, and
`--force` does not override it: `--new-cycle` is the explicit way to start
another. Rounds 3 to 5 of lexray#1780 were three standalone invocations, each
beginning with no memory that the cycle had already been told to stop, and no
brake evaluated again.

### The fix pass is measured from outside

`round_stop.fix_surface` reports the files a fix pass touched that no earlier
round had read — reported, gating nothing, per the instrument-before-gate rule.
`converged` says whether a stop was a clean finish rather than a cap or a veto.
`guard_ratio` is now permanently report-only, recorded as a decision rather than
left as a deferral.

### A deferral is a shape, not a severity

`file_deferral_issues` takes the word `shape`: a category or a substantive
single named item may become a GitHub issue, and a batch of sub-floor findings
gets board rows and never one. Anything unclassified falls through to batch,
which files nothing — under the old severity bands a spare tracker line was the
cheap error, and it is now the failure being fixed. The bands still work.

### CI that cannot run says so

Where a pull request's base branch appears in no workflow's trigger list, the
report says no run CAN exist and names the remedy — add the base to the
triggers — instead of printing an instruction nobody can satisfy. The reviewers
are told the same thing. lexray#1780 carried "do not merge, even if the review
below is clean" through all five rounds and was merged anyway, which is what a
gate becomes when it cannot be satisfied.

### The seats can see what the change claims

A reviewer prompt is rendered with the pull request's title and body, framed as
the author's assertion and not as fact. A claim the diff does not deliver was
not a reviewable finding before, because nothing in the prompt carried the
claim.

### Dials

`max_rounds` 2 → 6, a backstop against running forever rather than a
convergence mechanism — which makes `escalate_on.fix_injection` load-bearing,
and its 0.5 uncalibrated for the smaller, more serious population it now counts.
`fix_severity_floor` P3 → P4, so the P3/P4 tail sits inside
`low_severity_fix_lines`' budget rather than outside every rule.
`budget.tokens_per_pr` stays `null`. It was set to 20,000,000 here so six rounds
would be affordable, and reverted before this shipped: `Budget.dormant` holds only
while every ceiling is `null`, so setting one wakes the block for every repo on the
fleet — and a spend the board cannot confirm then refuses the round outright on the
unattended path, which is the autonomous loop. Six rounds were affordable anyway,
because dormant already meant no ceiling.
