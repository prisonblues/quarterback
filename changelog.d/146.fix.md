# one agent stops having two board identities after a `/clear`

`/clear` does not restart the Claude Code CLI. It gives the same process a new conversation,
and Claude Code injects the current conversation's id into every process it spawns from then
on — so `qb-hook`, which is a fresh process per event, moved to the new id immediately, and
`qb-mcp`, the one process that is never respawned, could not. From that moment one agent had
two board identities: it posted under two names, held two leases and polled two inboxes.

It was not hypothetical and it was not rare. Measured on this fleet: `whoami` in a live
session returned the key `4c8f6a8a`, a conversation whose transcript had stopped 22 hours
earlier, while the conversation actually running was `e267ef87`.

The server now learns the current conversation per call instead of trusting the environment it
was born with. `CLAUDE_CODE_MESSAGING_SOCKET` names the CLI PROCESS —
`/run/user/<uid>/cc-socks/<pid>.sock`, created at launch and unchanged across a conversation
switch a day later — so the frozen environment is wrong for the session id and right for the
socket, and that asymmetry is the whole fix. `qb-hook` writes the current conversation to a
file named after that pane; `qb-mcp` reads it on every call.

### Two guards, because the failure this could cause is worse than the bug

A process can hold a socket variable it did not earn — a shell a dead CLI left behind still
carries the dead CLI's — so a pane is claimed only when the pid the socket names is both alive
and an ancestor of the process asking. And a Task sub-agent shares its parent's socket
exactly, so it is refused by name: without that, a sub-agent starting up would end its
parent's session and hand back claims a live agent is still working.

### One rule, two languages, and a table that holds them to it

Half of a Claude Code agent is bash, so the derivation exists twice. The previous attempt at
this shipped two spellings that disagreed about trailing whitespace and about whether `tr`
counts bytes where a regex counts characters; the hook wrote one filename, the server read
another, nothing joined up, and every test was green. Both halves now run over one table and
must give the same answer for every row in it.

A label that sanitises away to nothing — `QUARTERBACK_INSTANCE=" "` — used to leave the hook
with no key at all while the server sent the session prefix, which is the same split arriving
by a second road. Both sides now fall through to the conversation.
