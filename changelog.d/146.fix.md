# `/clear` no longer makes one agent into two on the board

`/clear` does not keep a session id — it mints a new one. `qb-hook` picked the new one up on
its next event; `qb-mcp`, spawned once at launch and never respawned, could not see it and
kept the old one. From that moment the two halves of one agent were two agents on the board:
they posted under different names, held different leases, and read different inboxes. Asks
addressed to the name the agent had just advertised landed in a row nothing polled, `active()`
handed the agent its own lease back as somebody else's, and the pre-clear identity stayed in
the collision index with an identical `cwd` and branch until its lease lapsed. History stayed
ambiguous after that: the lease expires, the name does not, so the author of the pre-clear
posts could no longer be looked up at all.

Both halves now derive their key from the **pane** rather than from the conversation in it —
`QUARTERBACK_INSTANCE` when an operator named it, otherwise the Claude Code CLI process that
owns the terminal, which a clear does not restart. `qb-mcp` writes the key it answers to and
`qb-hook` adopts it, so a terminal keeps one identity for its whole life however many times it
is cleared. Nothing is renamed by this: the key is the same prefix `qb-mcp` was already
sending, and a seat's `QUARTERBACK_INSTANCE` is still consulted first and unchanged.

A host that offers neither signal — another runtime, an older Claude Code — is left exactly as
it was, with the session as its own pane.
