# the panel can now run a round WITHOUT the PR's claim, and the round says which arm it was

#631 gave the reviewer prompt the pull request's own title and body, framed as the
author's assertion rather than as fact. Before it the prompt carried five keys —
number, repo, base, the CI brief, the diff — and none of them was the claim, so a whole
class of defect was invisible to the panel by construction: *a PR asserts a measured
result and ships nothing that produces it*. The PR that prompted the issue asserted
117.9 MB → 8.16 MB, 14,199 → 0 and "verified end to end against the live FCA API", with
nothing committed that produces any of those numbers, and round 1's four vetoes were
all a seat saying it could not verify runtime claims — about claims it had never been
shown.

That mechanism shipped with its own condition unmet, and the issue said so at the time.
**Handing a reviewer a body that says "this is safe because X" primes it to accept X.**
A primed seat reports FEWER findings. Fewer findings look like a clean PR. So whether
the framing holds is not something to assert — it is something to measure, by running
the same PRs with and without the block and comparing the counts. If the seats go
quieter, the block is worse than nothing.

That measurement was not runnable. Two things were missing, and this is both of them.

### `review_panel.pr_claim`, and `panel.py --no-pr-claim`

An off switch, which is what a control arm is made of. It defaults **true**, so a repo
that never writes the key runs exactly the round it ran before; `false` is the pre-#631
posture, in which a claim the diff does not deliver is not a reviewable finding.

It is not a thoroughness dial anybody is expected to turn down, and the per-run flag is
the instrument rather than a convenience: the dial lives in `.harness-rules` **in the
repo under review**, so producing the control arm by editing that file would change the
very diff whose findings are being counted. A value that is not a real boolean falls
CLOSED and says so, on `reviewer_code_access`' rule — `bool("false")` is `True`, and a
hand-written `"pr_claim": "false"` must not become the setting's opposite on the one key
where the author was trying to stop the seats being primed.

### `pr_claim` and `pr_claim_sent` on `review_runs`

The panel already knew whether it had sent the block. It said so in `config_notes`,
which is a list of English sentences, so a population of rounds could not be partitioned
by whether it was primed: both arms could be run and the comparison would still be
unaggregatable. That is the same shape of defect `mc57fb9ba` fixed for the dials and
`mdef4716b` for the harness — a fact the round knew about itself, kept only in prose,
and therefore lost to every reader that is not a person.

**Two columns, and the split is the judgement.** `pr_claim` is the ARM the round belongs
to (what was asked for) and `pr_claim_sent` is whether the arm was delivered — the block
is charged against the tightest seat's diff budget and dropped whole where that budget
cannot carry the author's own words. A round that asked and dropped is in NEITHER arm;
told only what the seats got, an aggregation would score that round as a control and
read a budget effect as evidence about the framing, which is exactly the error the
measurement exists to avoid making. It is the split `0024` already made for
`code_access`, and its argument transfers without change.

Both ride the run LIST as well as the detail view, on `harness_digest`'s rule: their
entire purpose is a comparison over a population, and a field a reader has to fetch one
round at a time cannot partition one.

NULL on both is "the panel did not say" — every round recorded before the columns, and
every skip and refusal permanently. A round that dispatched no seat did not decline to
prime one, and `false` there would put a round that reviewed nothing into the unprimed
arm of a comparison it was never in.

### what this does not do

It does not run the experiment. That is real vendor-CLI spend on several PRs, twice
each, and it belongs with #626's roll-up, which is the thing that will have the
population to answer it. What changes here is that the question is now answerable at
all.
